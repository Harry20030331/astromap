# CS 153 Final Project Requirements

Course project: **The One-Person Frontier Lab**  
Relevant final submission component: **Project Video + GitHub Submission — 15 points**

This document keeps only the requirements relevant to the final project submission, plus compute-credit information.

---

## 1. Final Submission Deliverables

### Project Video

- A demo of the project.
- Must be **less than 3 minutes**.
- Should answer the video requirement questions listed below.

### GitHub Submission

- Clean, documented code.
- Code should be easily reproducible by others.

---

## 2. Project Submission Rubric

The final **Project Video + GitHub Submission** is graded out of **15 points**.

### Problem & Insight — 3 Points

- Project addresses a meaningful problem, research topic, or opportunity.
- Motivation is understandable and compelling.
- Approach is original, ambitious, and thoughtful.

### Execution & Technical Work — 5 Points

- Individual built, implemented, analyzed, or produced something substantial.
- The artifact is functional and understandable to use.
- Technical effort matches the project scope.
- Final result demonstrates iteration and meaningful progress.

### Evaluation & Evidence — 3 Points

- Project demonstrates attempts to validate claims or understand limitations.
- Evidence can include:
  - Benchmarks.
  - User feedback.
  - Expert feedback.
  - Comparisons.
  - Testing.
  - Citations.
  - Failure analysis.
  - Usage metrics.
- Different project types may evaluate success differently. This will be evaluated case by case for each project.

### Communication & Presentation — 2 Points

- Submission should be understandable to someone outside the team.
- This can include:
  - Demo video quality.
  - README clarity.
  - Documentation.
  - Presentation structure.
  - Reproducibility.
  - Ease of understanding and engagement.

### Process, Integrity & Disclosure — 2 Points

- Honest disclosure of AI usage.
- Sources and collaborators are credited.
- If the project forks or borrows base code from existing repos, those repos must be cited thoroughly along with the substantial changes made.
- Major decisions and limitations are discussed.
- Evidence of genuine effort over time.
- Public repo, commit history, or development artifacts are included when appropriate.

---

## 3. Video Requirements

### Q1: Why did you build what you did?

- What bottlenecks did you identify?
- What inspired you to develop this project?

### Q2: How exactly does the product work?

Depending on project type:

- **Research:** model training, training data, etc.
- **Application / Product:** product architecture, deployment, etc.
- **Automation / Agent Systems:** agent training, data, etc.
- **Domain-Specific Idea:** use whichever of the above categories fits best.

### Q3: Potential use cases of the product?

- What is the impact?
- How is this valuable to society?
- How do you envision people using this tool?

### Q4: What more would you add?

- Discuss future additions, improvements, or next steps.
